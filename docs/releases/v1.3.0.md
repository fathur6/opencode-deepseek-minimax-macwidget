# v1.3.0 — OpenAI 5-hour quota bar

## Highlights

- The OpenAI card now shows a labelled **5h** usage bar directly above the
  existing **Weekly** bar. Each row has its own remaining percentage,
  monochrome usage fill and server-anchored elapsed marker, and reset time.
- Both windows are read from the same authenticated
  `GET /backend-api/wham/usage` request and classified by
  `limit_window_seconds` (`18000` = 5-hour, `604800` = weekly) instead of by
  JSON position, so reversed or reordered payloads cannot be mislabelled.
- A missing, malformed or errored window no longer hides its sibling. Cached
  values are retained per window, so a failed refresh keeps the last known
  reading for each window independently.
- The weekly estimated cost (`Est. $…`) and the Remaining Quota chart remain
  anchored to the weekly 168-hour window only.

## Data compatibility

- The 5-hour reading is persisted additively in the existing
  `~/Library/Application Support/OpencodeWidgetApp/quota.db` ledger through two
  new nullable columns: `openai_five_hour_percent` and
  `openai_five_hour_reset_at` (Unix seconds).
- Migration is transactional and idempotent, uses `ALTER TABLE ADD COLUMN`
  only, and never rebuilds, drops, renames or backfills the table. Existing
  rows, `deepseek_usd`, `openai_percent`, input-token and estimated-cost
  columns, `recorded_at` values and `quota_month_mark` rows are unchanged.
- Legacy `widget-data.json` caches decode unchanged with the 5-hour fields
  nil.

## Verification

- `swift test`: 198 tests, 0 failures, including window classification in both
  orderings, invalid/missing/duplicate windows, per-window cached fallback,
  cache round-trip, cache-migration and ledger-migration preservation.
- Exactly one quota HTTP request per refresh (asserted by
  `DataFetcherTests.testHTTPAuthJSONAndTransportFailuresKeepBothCachedWindows`);
  the second bar adds no polling and the marker still ticks once per minute.
- Release `xcodebuild` succeeded; DMG verified with `hdiutil verify` and an
  ad-hoc `codesign --verify --deep --strict` pass.
- Live upgrade on the maintainer's Mac: 237 → 238 ledger rows (no rows lost),
  month mark preserved, summed estimated cost unchanged (230.544652), added
  columns present, `PRAGMA integrity_check` = ok, and the newest row populated
  with the live 5-hour percentage and reset time.

## Performance

Measured on the same Mac with comparable launch conditions:

- Idle CPU: 0.0% (baseline app also 0.0%).
- RSS after launch settles by ~60–90 s; the new build shows a short startup

## Caveats

- The `/backend-api/wham/usage` endpoint is undocumented and may change. The
  fetcher is deliberately tolerant and isolated in one file so a contract
  change stays a one-line fix.
- The app relies on the Codex OAuth session in `~/.codex/auth.json`. If the
  token expires or rotates, the card keeps the last cached readings until Codex
  refreshes the session.
- The DMG is ad-hoc signed, not notarized; first launch may require the usual
  Gatekeeper confirmation.
