# v1.5.0 — Native Provider Settings

## Highlights

- The menu footer now orders **Refresh**, **Settings**, then **Quit**. Settings
  opens the app's single native macOS Settings scene rather than a custom window.
- The compact Providers page is a bounded, approximately 440-pixel scrolling
  view. It uses standard macOS controls in the widget's monochrome presentation.
- DeepSeek, MiniMax, and OpenAI each have a compact provider row. Their card
  visibility takes effect immediately and persists; hiding all cards leaves the
  charts-only menu layout available.

## Behaviour and data boundaries

- Provider-card visibility is presentation-only. Collection, refreshes, charts,
  cache, and the local ledger continue unchanged regardless of the visible-card
  selection.
- DeepSeek and MiniMax credentials are validated with their provider before a
  Keychain save. Each provider resolves its credential from Keychain first, then
  falls back only to its existing OpenCode auth-file value as a read-only source.
- OpenAI shows Codex-session availability only. It can copy the literal
  `codex login` command but never initiates authentication and does not accept a
  platform API-key field.
- No API key or OAuth token is placed in the UI, logs, cache, ledger, public
  release notes, or the DMG.

## Verification

Phase 5 completed its native Settings and credential-boundary verification:
single-window Settings behavior, persisted provider visibility, charts-only
layout, presentation-only collection, Keychain-first resolution, validation
before save, and copy-only Codex guidance were all covered by the approved
automated and native checks. The release package is built from the committed
source revision and independently verified before publication.
